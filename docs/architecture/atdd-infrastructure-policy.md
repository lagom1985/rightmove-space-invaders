# ATDD Infrastructure Policy

Per `nw-distill` § Project Infrastructure Policy. One file per project: apply it if it exists, write it if it's absent, and rewrite it with `--policy=fresh`. Git history is the audit trail. Agreed with the user on 2026-10-23 (DISTILL, rightmove-invaders-sound; revised after the final review gate).

## Driving
| Port | Mechanism | Note |
|---|---|---|
| Keyboard in the game page | Playwright `page.keyboard` against the real page served by `npm start`, in Chromium, Firefox and WebKit | Real browser input pipeline. Playwright's key presses are US QWERTY; a second `keyboard.down` of a held key carries `repeat: true`; `CapsLock` doesn't change the `key` it reports (DISTILL probe, rightmove-invaders-typed-initials, 2026-10-25) |
| Keyboard in the game page, other layouts (synthetic key events) | `new KeyboardEvent('keydown', { key, code, bubbles: true, cancelable: true, ...modifiers })` dispatched on `window` through `page.evaluate`, then its keyup, against the same real page: AZERTY's `a` on `KeyQ`, QWERTZ's `z` on `KeyY`, `m` on `Semicolon`, `é` on `Digit2`, Option's `å` and Windows' Alt+A (`a`), each with `altKey`, and a Caps Lock capital | Added by DISTILL (rightmove-invaders-typed-initials, DDD-T11). The probe showed the page's own listener receives them, with `key`, `code`, `repeat` and the modifiers as given, in all three engines. They are untrusted (`isTrusted` false): the typed presses take them, the positions ignore them (ADR-009, 2026-10-27), so they type initials but can't play. They run no browser default: so a real AZERTY or QWERTZ keyboard is a manual check (DoD 5). Every keydown gets its keyup, as a real key press does |
| What the game leaves to the browser (`defaultPrevented`) | A keydown recorder added with `page.evaluate` once the page has loaded, so it runs after the game's own listener and reads `defaultPrevented` as the game left it, for real and synthetic key presses alike | Added by DISTILL (rightmove-invaders-typed-initials, DDD-T8). It proves the game's decision, not the browser's behaviour: Firefox's quick find (`/`, `'`, typeahead find) and Backspace navigation are manual checks (DoD 5) |
| The typed entry's rules on their own (`handlePresses(pressed, typed)`, `src/game/game.js`) | A fresh copy of the module per run (`tests/unit/support/fresh-game.js`), handed each frame's presses as plain data, the positions as a set and the typed presses as `[{ key }]` in order (DESIGN L-2), by the Tier B model (`fc.commands`, project `in-memory`) | Added by DISTILL (rightmove-invaders-typed-initials). Plays `main.js`'s part and the keyboard's reporting; never hands over a repeat or a chord (the adapter's filter is DELIVER's unit test over a plain `EventTarget`). Reads the rules only through `snapshot()` (`entry = { letters, notice }`, `skipped`) and the published events; the one sanctioned internal access is arranging a game over through the checked `arrange.deposit` and `arrange.formationOnPin` |
| Window focus and tab visibility | `blur` on `window`; `visibilitychange` with `document.visibilityState` overridden to `hidden` | Real listeners; no frame runs before the assertion |
| Window `resize` (`main.js`'s listener → `renderer.resize()` → the backdrop store's `rescale(k)`) | **None automated: a recorded gap, waived** | **Waiver (user, 2026-10-26; rightmove-invaders-level-backdrops DESIGN DDD-B13, F8)**: no scenario drives the wiring, because the browser walking skeleton never resizes and the canvas isn't read (D10). The store's `rescale`, with a new scale and with the same one, is checked in memory at the store's port. The wiring is checked by hand in DELIVER: "a resize during the fade" (the feature delta's Rendering universe) |
| Sound director `handle(event)` | Direct call from Node step definitions (project `in-memory`) | Layer-2 acceptance for states that are slow to reach by playing |
| High-score table service `handleScores(request, port, { now, newId, log, where })` | Direct call from Node step definitions with a Web `Request` (project `in-memory`, tag `@server`), through the production restricted port (`createTablePort`) over the real `@netlify/blobs` 11.1.6 client and a real `BlobsServer` in a fresh temp directory per scenario (deleted after it) | Decided in DESIGN (user, 2026-10-24; DDD-4, DDD-19); added by DISTILL (rightmove-invaders-leaderboard). Runs in the Netlify build gate with no browser. **The harness (`steps/table-service.js`) is a second composition root**: the Netlify entry cannot run locally, so it builds store -> test store port -> `createTablePort` -> `handleScores` by hand, with `where = { scope: 'local', context: 'missing', published: 'missing' }` as `scripts/serve.mjs` will pass it, the exception DDD-4 sanctions (the roots wire the port, clock, id source and logger). So that the entry and `scripts/serve.mjs` wire the same pieces is DELIVER's unit test (a fake deploy environment over a real `BlobsServer`). **Raw access**: arranging writes keys, and observing lists the store, straight on the emulator `Store`, bypassing the port; observing must not move the server clock (asserted in `snapshot()`). Every When goes through the handler. Not modelled: Netlify's 429, the CDN cache, a missing deploy ID (the last is the DELIVER unit test's alone) |
| Score API with sessions and records: `handleSessions` and `handleScores(request, port, { now, newId, log, where, sessions, clockAllowanceMs })` | The leaderboard's table-service harness, extended (`ScoreApi` in `tests/e2e/rightmove-invaders-replay-verified-scores/acceptance/steps/score-api.js`, project `in-memory`, tag `@server`): the same production port over a real `BlobsServer`, a request dispatched by path as the roots will. Both handlers get `sessions`, a signer the harness builds from a known test secret as the roots build theirs (DDD-R17), or null for a root with no secret, and `clockAllowanceMs` of 10 s, production's: the harness never lets a game through faster. **Sessions are arranged, never acted**: issued through the production `handleSessions` over the raw store, on the table's own clock, their log lines dropped. A signing that carries a record has its session issued as long before as the game lasted, plus a second, unless the scenario is about the clock. **How a signing is made follows `TABLE_PROTOCOL`** (the leaderboard's `domain-types.js`): bare, with a session (slice 01), or with a session and a played game's record (slice 02 on), so the leaderboard's own server scenarios keep checking what they checked. **Observing adds** a reading of the table taken the moment a signing's write reaches the store (the test store port's `afterWrite`), through the production handler over the raw store, so it moves no clock and adds no log line; and the game id, computed by the harness on its own (SHA-256 of the seed's 32 characters, first 32 hex) | Added by DISTILL (rightmove-invaders-replay-verified-scores, 2026-10-26). Not modelled: Netlify's 429 on `/api/sessions` (one counter for both paths: DEVOPS's probe and S6), the secret in a deploy context (the smoke test), clock skew between instances (inside the 10 s allowance, ADR-008's edge) |
| The rules played in Node, to make honest records (`createGame` and scripted players, `tests/common/played-games.js`) | The real rules, one game per instance, played to an exact deposit by a player that aims at the bottom hurdle worth the most that still fits (seeds tried in a fixed order, each found in milliseconds), or standing still and firing (the smoke test's scripted game), or the probe's greedy bot. The record is the one the game hands its signing (`initialsEntered`), so a server scenario signs what a browser would; the player checks that the record's steps are the steps it played (DDD-R8) | Added by DISTILL (rightmove-invaders-replay-verified-scores). Not a double: it is the production rules, used to arrange. It can't produce a game worth more than about £20,000 in a test's time, so an example that claims more is refused before the replay or retired |
| High-score rules on their own (`src/game/game.js`) | A fresh copy of the module per run (`tests/unit/support/fresh-game.js`), with the table's answers handed over in any order by the Tier B model (`fc.commands`, project `in-memory`) | Added by DISTILL (rightmove-invaders-leaderboard). Plays `main.js`'s part; the network, the 5000 ms timeout and the views are the browser scenarios'. The model reads the rules only through the read-only `snapshot()` that `game.js` exports; the one sanctioned internal access is arranging a game over, only through the checked `arrange.deposit` and `arrange.formationOnPin` of `tests/unit/support/fresh-game.js` |
| Backdrops on their own (`src/view/backdrop.js`: `backdropPlan`, `paintBackdrop`, `createBackdropCache` with `rescale` and `canvasFor`, and the shell `showBackdrop`) | A direct call from Node (project `in-memory`) to these internal view units: a deviation from Mandate 1, by the user's choice of the recording context (2026-10-26; Deviations below). Painting goes onto a recording 2D context (`createRecordingContext` in `tests/unit/support/fake-canvas.js`, `RECIPE_CALLS`) that records the calls and the fill and stroke styles, never pixels, and refuses any call the recipes don't make, as `fake-status-root.js` does. The shell draws on a second recording context that stands for the screen's (`SCREEN_CALLS`: `drawImage`, `fillRect`, `save`, `restore`, `fillStyle`, `globalAlpha`), which records each draw with the strength it was made at; it is handed the real store behind a watch that forwards `canvasFor` and refuses anything else. The store gets the stand-in canvas factory of the same file (the Driven row below). Over a climb, the plan and the shell are fed each frame from a fresh copy of the rules (`tests/unit/support/fresh-game.js`, later rungs reached through the checked `arrange.lastHurdleShot`), with the real status mirror on `fake-status-root.js` | Decided by the user (2026-10-26, DISTILL, rightmove-invaders-level-backdrops; revised after the Final Wave Review Gate). The real canvas in the browser stays not asserted on (waiver D10). The climb harness plays one fixed step per frame in the order `main.js` plays a frame, and makes the call DESIGN gives `render.js`, `showBackdrop(ctx, backdropPlan(frame), store)`. It stands in for `main.js`'s loop and for `render.js`, and is neither: that `render.js` makes the call is checked by hand. It cannot model pixels, real allocation limits, the cost of a build, or a built canvas that fails when drawn (assumed not to happen, DESIGN's catalogued lies). `Math.random` is locked (a stub that throws and counts) only for the duration of each painting call, because the test runner itself uses it between steps |

## Driven internal (real)
| Port | Mechanism | Note |
|---|---|---|
| Persistence (localStorage) | Real browser storage, fresh BrowserContext per scenario | Blocked storage is simulated with an init script that makes `localStorage` throw |
| Recorded-games corpus (`tests/fixtures/recorded-games/`) | Real files, one JSON per game `{ seed, record, deposit, steps }`, made on demand in Node by `node scripts/record-corpus.mjs` (`tests/common/recorded-games.js`), which refuses to overwrite a game recorded on the rules version the game plays now; the check only reads them. Signed through the table in Node (the Score API harness, project `in-memory`, the build gate), and played back by the production `replay.js` loaded into a page of the local server in each browser project (the Mandate 1 deviation below) | Added by DISTILL (rightmove-invaders-replay-verified-scores, K21). Re-recorded only after a `RULES_VERSION` bump, never to make a failing check pass |
| High-score table (`/api/scores`) | The real Netlify Function and the real `@netlify/blobs` client, mounted by `scripts/serve.mjs` against the local `BlobsServer` emulator (fresh temp directory per server start) | Added 2026-10-24 (SPIKE, rightmove-invaders-leaderboard). One table per scenario through a `test-board` cookie, which only the local server reads; "another computer" is a second BrowserContext with the same cookie. The emulator is not production: it returns no etags on reads and is not atomic, so nothing etag-based is proven locally |
| Accessibility tree (status mirror) | Real DOM, read via `role=status` and `[data-hud]` | |
| Screen (canvas) | Real canvas, not asserted on: **no test reads the canvas** | **Waiver (user, D10; widened by the user's acceptance of rightmove-invaders-level-backdrops DDD-B13, 2026-10-26)**: nothing drawn on the real canvas is asserted, in any project. Each feature's Rendering universe is a manual check in DELIVER: the HUD indicator and controls line (leaderboard), the typed-initials slots and lines, and the backdrops, their fade, the flat fail-safe and the skylines (level-backdrops). In memory, the backdrop shell's calls are recorded on a stand-in context (the Driving row "Backdrops on their own"): calls and strengths, never pixels |
| Offscreen canvas factory (`createCanvas`, injected into the backdrop store `createBackdropCache`) | In the browser, the real `() => document.createElement('canvas')` that `render.js` hands the store (the walking skeleton, not asserted on, D10). In memory, the stand-in `createFakeCanvasFactory()` of `tests/unit/support/fake-canvas.js`: canvases 300 by 150 until sized, whose `getContext('2d')` gives a recording context, or null when the screen "has no room", and whose draws throw part-way when it "loses its drawing" | Added by DISTILL (rightmove-invaders-level-backdrops, 2026-10-26). A real allocation failure (canvas memory limits, a lost GPU) can't be produced on demand in a browser, so its failure modes are the stand-in's only. It refuses anything else asked of a canvas, and keeps every refusal, even one the store's fail-safe swallows |

## Driven external / non-deterministic (fake)
| Port | Fake | Note |
|---|---|---|
| Clock | Playwright `page.clock` (`install` → `pauseAt` → `runFor`) | Fast-forwards the game; the Web Audio clock still runs on real time, so tests assert on what started, never durations |
| Randomness (`Math.random`) | Seeded PRNG (mulberry32, fixed seed) installed by an init script before the page loads | Every run plays the same game; property tests use fast-check seed 20261023 unless `FC_SEED` is set. **Each page its own seed** (SEED, then SEED + 1, … per scenario; rightmove-invaders-replay-verified-scores): `main.js` draws each game's seed from it, and two pages that drew the same seed would play the same game, which signs once (D7). The choreography (one shot at the Damp above the pin, then standing still) doesn't depend on the seed: the shot lands before the first bolt, and no shield stands over the centre |
| Audio output (Web Audio) | **Real** Web Audio in the headless browsers, observed through the synth's journal (ADR-003) | Deliberately real: local and free; verified headless in all three engines, and its clock runs on real time under the fake clock. Cursors use the journal `seq`, never the array index (the journal keeps the last 100). Director scenarios use an in-memory cue model and a reference plan instead. On the synth-only test page, `window.synth` is a test-only hook |
| Network between the page and `/api/scores` | One `page.route('**/api/scores*')` dispatcher in the page driver: abort ("can't be reached", "loses the connection"), a 503 (`not-saved`, "turns the signing away"), hold with no answer (pending, and the 5000 ms timeout on the fake clock), and "late" (a load looked up from the real function at once, its answer handed over later) | Decided in DESIGN (user, 2026-10-24; DDD-16, ADR-008); added by DISTILL. Everything not faulted reaches the real function. Other house-hunters sign through `context.request`, which `page.route` doesn't intercept. The clock is never moved on while an answer is held, except to test the timeout. **Sessions** (rightmove-invaders-replay-verified-scores): the dispatcher also routes `/api/sessions`; the game-start session request is a load to the leaderboard's faults, and this feature's driver answers it at once, 3 s of game time later, with a failure or never, and notes the seed sent and the session answered. A forger's change to the deposit a signing carries is made there too (`route.fetch` with a new body). "The table everyone reads" is a GET through `context.request` |
| Server clock, id source and logger (table service) | Injected `now()` (starts at 2026-01-01T09:00Z and moves on 1 s whenever a listing returns; can be frozen), `newId()` (`t1`, `t2`, … base 36; or one repeated id; or one that can't be part of a key) and `log()` (every entry kept) | Decided in DESIGN (user, 2026-10-24; DDD-4, DDD-12, DDD-17); added by DISTILL. Forces the duplicate-key path, a key the port must refuse, and shows whether `listedAt` was taken after the listing. **Sessions** (rightmove-invaders-replay-verified-scores): the same clock issues sessions; a scenario sets it to any moment to give a session its age (1 h 59 min, 2 h 1 min, 11 s in the future, a game's length less 10 or 11 s), and an arranged signing moves it on a second, so the next signing is never the same key |
| Session secret | `@server`: a known test secret, 32 bytes in canonical base64 (`TEST_SECRET`), or none (`sessions: null`). Browser: `scripts/serve.mjs` draws 32 random bytes at each start. Production's and the previews' values never reach a test, and are never `TEST_SECRET`, which is public | Added by DISTILL (rightmove-invaders-replay-verified-scores; DDD-R2, E1). Whether the secret reaches the function is S2's on a preview; production's is the owner's (the UI check, the release-day game, the rotation `curl`); branch deploys have no check and fail closed without it |
| Test-only routes and switches of the local server: `POST /__test/rows` (DDD-R17) and `test-clock=lenient` (DDD-R11) | `scripts/serve.mjs` only, and only for a request with a `test-board` cookie: the route puts another house-hunter's row on that board through its port, with a random id; the cookie skips the clock check. Never in `src/**`, `netlify/**` or `dist/` | Added by DISTILL (rightmove-invaders-replay-verified-scores, E1, E6). Guarded by a token rule in `tests/unit/layering.spec.js` (DELIVER, before E1), by M8's scenario sending the cookie to the function's handler, and by the build copying only `index.html` and `src/` |
| The clock check, in the browser (D8) | Every page carries the cookie `test-clock=lenient`, which only `scripts/serve.mjs` reads, and only with a `test-board` (DDD-R11, E6): the browser scenarios play on a fake clock much faster than real time. The one exception, "The browser's clock plays no part", clears the cookie and plays a whole game in real time, with the page's clock installed an hour off and never paused; its waits are real | Added by DISTILL (rightmove-invaders-replay-verified-scores). The `@server` scenarios never skip the check |
| Store failures (table service) | The test store port: a `Proxy` around the real emulator `Store` that forwards every call and, on request, throws on `list`, `set` or `delete` (the error message carries a key, to check the log never repeats it) | Decided in DESIGN (user, 2026-10-24); added by DISTILL. The one sanctioned double. It wraps the emulator `Store` for the handler's calls only; the harness's own arranging and observing use the raw `Store` (see the table-service row). Cannot model: partial writes; latency or timeouts inside Blobs; stale (eventually consistent) listings; a `set` that reports "not modified" for any reason but an existing key; Netlify's 429; a missing deploy ID. It assumes `list()` resolves to `{ blobs }`. **Emulator lie found by DISTILL**: a listing taken during concurrent writes can come back short, even empty, with a 200 (its walk does `readdir` then `stat`, and a temporary file renamed in between ends it on `ENOENT`), so locally a signer's own answer under a burst is not checked; K11 checks it on Netlify |

## Deviations from the nWave mandates (DISTILL: rightmove-invaders-leaderboard, 2026-10-24; rightmove-invaders-level-backdrops, 2026-10-26; rightmove-invaders-replay-verified-scores, 2026-10-26)
- **State-delta port** (`tests/common/state-delta.js`, Mandate 8): it ships `unchanged`, `setTo`, `appendedWith`, `prependedWith`, `containing`, `normalizedTo` and `satisfying` (a rule instead of a value, for "at most 5 removed, all ranked 11th or lower"). `idempotent_after` and `legacy_healed` are not ported: they model installer re-runs and legacy-state healing, and nothing here needs them. Add them when a scenario does.
- **Mandate 9** (PBT only at layers 1-2): the OUT-9 `@property` runs fast-check over real emulator I/O (layer 3), by decision of the user. It is affordable because the emulator is in-process (about 2 ms to start, tens of ms per batch) and bounded to 20 runs of up to 30 signatures. A timing flake would fail the Netlify build. There is no scheduled run (no GitHub Actions): the build gate is the property's only run, so on a timing failure the owner re-runs the build with a rotated `FC_SEED` and records the seed, and a failing seed is replayed with `FC_SEED=<seed>`.
- **Build-gate server**: Playwright's global `webServer` starts `scripts/serve.mjs` (and its `BlobsServer`) for every run, `unit` and `in-memory` included; it cannot be skipped per project, and the config is not changed for it (see the feature-delta, "Wave: DISTILL / [REF] Test placement").
- **Mandate 1** (driving ports only; rightmove-invaders-level-backdrops): the in-memory drivers call internal view units directly: `backdropPlan`, `paintBackdrop`, `showBackdrop` and the store `createBackdropCache` (`rescale`, `canvasFor`), on recording 2D contexts. This is the user's choice of the recording context (2026-10-26), because the driving port, the keyboard on the real page, can't show a backdrop without reading the canvas (waiver D10), and DESIGN adds no seam into the game (DDD-B13). The real driving port is covered by the browser walking skeleton alone, which reads the status mirror. What the direct calls can't prove, that `render.js` makes the call and `main.js` reaches `rescale` on a resize, is checked by hand (the Rendering universe).
- **Driving adapter verification** (rightmove-invaders-level-backdrops): window `resize` has no automated scenario, a gap the user accepted (2026-10-26, DESIGN DDD-B13, F8). See the Driving row "Window `resize`".
- **Walking skeleton green at hand-off** (rightmove-invaders-replay-verified-scores): the feature extends the leaderboard's walking skeleton, which is inherited and green in three engines, and adds one at the server's port, "The owner's table turns away a signing that no game asked for". That one asserts what slice 01 builds (today the table saves the signing), so it is `@pending` at hand-off and is DELIVER's first scenario. The end-to-end path it uses, the handler on the real emulator, is already green under the leaderboard's server scenarios.
- **Mandate 1** (rightmove-invaders-replay-verified-scores): milestone 6's browser scenario, "Every recorded game plays back as it was recorded, in this browser", loads the production replay (`src/game/replay.js`) into a page of the local server and calls it, as DESIGN's DDD-R12 prescribes (accepted by the user, 2026-10-26). No driving port runs the replay in a browser, and that every engine plays the same game is K21's point. The recorded games in Node go through the table's driving port (signed through the Score API harness).
- **Mandate 9** (rightmove-invaders-replay-verified-scores): the one-row-per-game `@property` runs over real emulator I/O (layer 3), as the leaderboard's OUT-9 property does: 20 bursts of 2 to 5 signings, sometimes one sent ahead, with 1 to 3 readers, generated with `fc.sample` from seed 20261023 unless `FC_SEED` is set. Its only run is the build gate, as above.
